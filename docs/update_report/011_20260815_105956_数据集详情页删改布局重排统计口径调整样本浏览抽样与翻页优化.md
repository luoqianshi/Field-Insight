## 一、需求背景

用户对数据集浏览详情页提出 8 项删改需求，集中在三点：界面信息冗余清理、统计报告口径调整、样本浏览性能与展示方式优化。

1. 右下角不需要冗余的【删除数据集】组件，删除数据集保留在右上方即可。
2. 【数据划分】的数据在顶部导航栏存在，不需要在底下再次重新出现。
3. 【数据集结构】矩形框的底部与【类别列表】的底部对齐，下方整行放置完整的【数据统计分析报告】。
4. 【标注框面积分布】不需要统计；改为统计每张图片的实例数量，绘制直方图并计算整个数据集平均每张图片实例数。
5. 【目标尺度分布】不只统计全集，还要分训练集、验证集、测试集一起展示。
6. 【数据规模统计】不仅统计不同划分数据集的图片数量，还应同时包含实例数量。
7. 移除【数据质量告警、类别分布失衡】相关功能。
8. 【样本浏览】无需加载所有样本，只需每个数据子集随机加载 5% 数量的样例示意图；另修复当前翻页功能存在的 bug（实测确认为**翻页慢/卡顿**）。

## 二、方案设计

### 2.1 布局重排（需求 1/2/3）

- 删除右列【危险操作区/删除数据集】整块卡片，删除功能仅保留页头右上角（含「删除文件」复选框）。
- 删除左列【数据划分】卡片整块（顶部 5 列统计卡已包含训练/验证/测试集数量与划分信息）。
- 两列布局由 `grid grid-cols-3` + `col-span-2 space-y-5` 改为 `items-stretch` 等高分栏：左列【数据集结构】卡片 `h-full`，右列【基本信息】+【类别列表】使用 `flex flex-col`，【类别列表】`flex-1` 拉伸，使两列卡片底部齐平。
- 【统计分析报告】与【样本浏览】移出两列布局，作为独立全宽块置于下方，独占整行。

### 2.2 统计报告口径调整（需求 4/5/6/7）

- 删除 `_compute_heavy_stats` 中面积收集、`area_hist` 直方图、类别失衡 `warnings` 生成逻辑；`_histogram` 方法保留复用。
- 新增每图实例数统计：遍历图片收集 `per_image_counts`，产出 `image_stats.instances_per_image = {hist, avg, max, min}`，其中 `hist` 用新增的 `_int_histogram`（取值范围 ≤20 时逐整数值一桶，否则 20 等分桶）。
- `_coco_size_dist` 改为按 split 分桶，产出 `bbox_stats.size_dist = {all, train, val, test}` 四组 small/medium/large 比例。
- 报告缓存引入模块级 `REPORT_VERSION = 2`，旧 `report_cache` 自动失效，无需用户手动重新生成。
- 前端规模统计表格新增「实例数」列（取 `report.summary.splits[x].object_count` 与 `total_objects`）。

### 2.3 样本浏览 5% 抽样 + 翻页性能优化（需求 8）

- 翻页慢根因（实测确认）：`list_images` 每次请求对 split 目录 `sorted(iterdir())` 并对**每张**图 `Image.open()` 读取尺寸（train=10707 张），单次请求约 1s+ 且随数据量线性增长；前端无 loading 态、无请求竞态保护。
- 后端：新增 `_image_index` 实例缓存（仅 `entry.stat()`，不打开图片），key 为 `f"{dataset_id}:{split}"`；`list_images` 新增 `sample_ratio` 与 `seed` 参数，抽样结果排序后缓存到 `_sample_cache`（同 seed 翻页稳定）；`delete_dataset` 时调用 `invalidate_image_index` 清理缓存。
- 前端：`loadImages` 传 `sample_ratio: 0.05`，新增 `imagesLoading` loading 态与 `loadSeq` 序号竞态保护。

```ts
async function loadImages() {
  const seq = ++imagesLoadSeq
  imagesLoading.value = true
  try {
    const res = await datasetsApi.fetchImages(id.value, {
      split: currentSplit.value, page: imagesPage.value, page_size: imagesPageSize,
      sample_ratio: SAMPLE_RATIO,
    })
    if (seq !== imagesLoadSeq) return // 竞态保护：丢弃过期响应
    images.value = res.data.images
    imagesTotal.value = res.data.total
    imagesTotalPages.value = res.data.total_pages
  } catch (e: any) {
    if (seq !== imagesLoadSeq) return
    images.value = []
    imagesTotal.value = 0
    imagesTotalPages.value = 1
  } finally {
    if (seq === imagesLoadSeq) imagesLoading.value = false
  }
}
```

```python
def _build_image_index(self, dataset_id: str, split: str) -> Dict[str, dict]:
    key = f"{dataset_id}:{split}"
    if key in self._image_index:
        return self._image_index[key]
    cfg = self.get_dataset(dataset_id)
    img_dir = self._image_dir_for_split(cfg, split)
    index: Dict[str, dict] = {}
    if img_dir.is_dir():
        for entry in sorted(img_dir.iterdir()):
            if not entry.is_file() or entry.suffix.lower() not in IMAGE_EXTENSIONS:
                continue
            try:
                index[entry.name] = {"size_bytes": entry.stat().st_size}
            except OSError:
                continue
    self._image_index[key] = index
    return index
```

## 五、经验总结

1. **翻页性能问题的通用根因模式**：列表分页接口在每次请求中对全量文件逐张做重 IO（PIL 解码取尺寸），是典型 O(n) 且无缓存的设计。解决思路：把"构建文件清单"与"分页切片"解耦，索引只做 stat 并缓存，分页在内存索引上切片，二次请求 O(1)。类似场景（大目录浏览）可直接复用该模式。
2. **随机抽样的稳定性**：用固定 seed 的 `random.sample` + 抽样结果排序后再缓存，可保证翻页/来回切换 split 时样例不跳动；若需"换一批"能力，可改变 seed 并在 key 中体现。
3. **报告缓存版本化**：统计报告结构变化时，仅靠"缓存不存在"判断不够，应给缓存加结构版本号（如 `REPORT_VERSION`），口径变更时旧缓存自动失效，避免前端因缺字段报错或展示错误数据。
4. **布局等底对齐**：CSS Grid `items-stretch` + 列内 `flex flex-col` + 子卡片 `flex-1` 是让两列不同高度卡片底部齐平的简洁方案，无需 JS 测高。
5. **测试口径同步**：删除某统计功能（如告警）时必须同步更新/替换依赖它的测试，并新增对新口径（每图实例数、抽样）的断言，防止回归。
