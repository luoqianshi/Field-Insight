## 二、方案设计

### 2.1 版本与命名约定

- 语义化版本 `vX.Y.Z`；git tag 与 [package.json](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/electron/package.json) 的 `version` 字段保持一致（当前 `1.0.0`，仓库尚无任何 tag，首发即 `v1.0.0`）。
- 发布产物命名：`TianJianZhiKan-v1.0.0-win-x64.zip`；Release 标题 `v1.0.0`。
- 构建产物不入库（`dist/` 等已被 [electron/.gitignore](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/electron/.gitignore) 忽略），分发完全依赖 GitHub Release 附件。

### 2.2 标准发布流程（手动 + 脚本辅助，暂不上 CI）

1. **冻结代码**：后端 `pytest` 通过、前端 `npm run build`、桌面 `npm run smoke` 冒烟通过。
2. **定版本号**：修改 `electron/package.json` 的 `version`（唯一版本源），提交 `chore(release): v1.0.0`。
3. **重建产物链**：前端 build → `build-backend.ps1`（PyInstaller 冻结后端）→ electron-builder 出 zip。
4. **验证产物**：zip 解压到干净目录运行冒烟；计算 SHA256。
5. **打注解 tag**：`git tag -a v1.0.0 -m "首个桌面正式版"`。
6. **推送**：按 AGENTS.md 强制走本地系统代理 push commit + tag（先探测代理端口，使用单次 `-c http.proxy=...` 参数）。
7. **创建 Release**：`gh release create v1.0.0 --title "v1.0.0" --notes-file <notes.md> <zip> <zip.sha256>`（或网页上传）。Notes 固定结构：亮点 / 修复 / 已知问题 / 使用说明（解压后运行 TianJianZhiKan.exe）/ SHA256 校验。
8. **发布后核对**：下载链接可用、解压可运行。

- 可选配套：一键「重建后端 → 打包 → 压缩 → 生成 SHA256」发布脚本（本次未创建）。

## 三、改动详情

**本次无代码改动**。以下为现状核查结论（全部来自实际扫描与文件读取）。

### 3.1 win-unpacked 定性

`electron/dist/win-unpacked/` 是 electron-builder `--dir` 模式产出的**免安装绿色版程序目录**，实测总体积 **1,115 MB（约 1.1 GB）**：Electron 壳 + 前端资源（`resources/app.asar`）+ 冻结后端（`resources/backend/`）全部就位，双击其中 `TianJianZhiKan.exe` 即可运行。它是打 zip / 做安装包的**原材料**，只发 Win 压缩包时，最终发布物即该目录的 zip。

### 3.2 exe 产物分类（排除 node_modules 与 .cache 后共 8 个）

| 类别 | 文件（相对 electron/） | 实测大小 | 说明 |
|---|---|---|---|
| 最终程序（随 zip 分发） | `dist/win-unpacked/TianJianZhiKan.exe` | 180.0 MB | Electron 主程序，用户双击入口 |
| 最终程序（随 zip 分发） | `dist/win-unpacked/resources/backend/TianJianZhiKanBackend.exe` | 26.6 MB | PyInstaller 冻结的 Flask 后端，由 main.js 自动拉起 |
| 依赖/附带（不用管） | `dist/win-unpacked/resources/elevate.exe` | 0.1 MB | 打包工具附带的提权辅助程序 |
| 依赖/附带（不用管） | `dist/win-unpacked/resources/backend/_internal/torch/bin/protoc.exe` | 2.7 MB | torch 自带依赖 |
| 中间产物（不分发） | `backend-dist/TianJianZhiKanBackend/TianJianZhiKanBackend.exe` | 26.6 MB | PyInstaller 载荷，被 extraResources 拷入 resources/backend |
| 中间产物（不分发） | `backend-build/desktop_backend/TianJianZhiKanBackend.exe` | 26.6 MB | PyInstaller workpath 构建残留，可清理 |
| 历史产物（可删） | `dist/TianJianZhiKan Setup 1.0.0.exe` | 367.1 MB | 早前 NSIS target 构建的安装包；`dist/builder-debug.yml` 中仍含 nsis 段可佐证 |

**核心结论**：真正属于"本程序"的只有 2 个 exe（壳 + 后端）；发布 zip 时不需逐个挑选 exe，**整个 win-unpacked 目录压缩即可**。

## 五、经验总结

1. **exe 多 ≠ 产物多**：Electron + PyInstaller 双冻结链路会在工具链缓存、workpath、extraResources 源、最终目录四处留下 exe 副本；识别时按「最终程序 / 依赖 / 中间产物 / 历史产物 / 工具链」五类划分，只关注最终目录内的 2 个主 exe。
2. **win-unpacked 是原材料而非发布物**：`--dir` 产物可直接运行，但对外分发必须再压缩（或制安装包）；配置从 nsis 切到 dir 后，旧 Setup exe 会滞留 dist，易造成发布拿错文件，应定期清理。
3. **版本单一来源**：以 `electron/package.json` 的 `version` 驱动产物命名（`artifactName` 模板），tag 与之对齐，避免多处版本号漂移。
4. **只发 zip 的最小改动**：`win.target` 增加 `zip` + `artifactName` 模板即可，`publish: null` 保持手动发布；无需引入自动更新体系。
5. **未签名分发的预期管理**：SmartScreen 提示属正常现象，Release notes 必须预先说明，减少用户疑虑。
6. **规划与实施分离归档**：未落地的方案不得写成"已完成"，报告状态如实标注"方案已定，尚未实施"，后续实施后可增补或另起报告。
