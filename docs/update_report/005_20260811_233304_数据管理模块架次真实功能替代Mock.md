## 一、需求背景

PRD 文档（`PRD_基于无人机图像的大田农作物智能监测与管理系统_v4`）要求数据管理模块支持真实的架次登记。原实现全部基于静态 mock 数据（`backend/mock/batches.json`），无法对接真实数据。用户提出以下原始需求：

1. `data/` 目录是 PRD 中提到的【原始图片仓库】，现已存放真实采集的 3 个批次大田甘蔗幼苗数据集（`sugarcane_20250419_5m/8m/10m`）。
2. 按架次登记的功能，注册信息以 **YAML** 形式存放，目录为项目根 `data/`。
3. 系统主要支持本机，数据批次注册可选用本机上其它可访问路径作为图片数据来源。
4. 用真实功能替代 mock 数据。

## 二、方案设计

### 2.1 总体架构：参考 ModelRegistry 模式新建 BatchRegistry

后端新增 `BatchRegistry` 类，设计上完全对齐项目已有的 `ModelRegistry`（`backend/core/registry.py`）：
- **YAML 持久化**：架次配置存于 `data/batches.yaml`，字段顺序统一（`_BATCH_FIELD_ORDER`），`image_formats` 用内联列表（flow_style）。
- **启动自动扫描**：`BatchRegistry.load_from_yaml()` 在 Flask 启动时调用，扫描 `data/` 一级子目录，自动发现并注册未在./mock 的图片文件夹。
- **内存图片索引**：扫描时用 Pillow 读取每张图尺寸，缓存于内存 `_image_index`，支持分页查询，避免重复磁盘扫描。
- **动态缩略图**：`get_image_preview()` 按需生成 400px 缩略图 / 1920px 中图 / 原图，不落盘。

### 2.2 自动扫描与元数据推断

- 文件夹名解析格式 `{crop}_{date}_{altitude}m`（如 `sugarcane_20250419_5m`），映射到作物中文名、采集日期、飞行高度。
- 无法解析时：`crop_type="未知作物"`、日期取文件夹 mtime。
- **忽略列表机制**：用户删除自动扫描注册的架次时，其文件夹名写入 `ignored_folders`，下次启动跳过，不会被重新注册。

### 2.3 API 接口（对齐 PRD 元数据结构）

8 个真实接口，统一响应信封 `{success, data, message}`：

| 方法 | 路由 | 说明 |
|------|------|------|
| GET | `/api/batches` | 架次列表（支持 crop_type/flight_date/plot_name 过滤）+ summary 统计 |
| POST | `/api/batches` | 登记新架次（校验路径、数量≤2000、单张≤50MB） |
| GET | `/api/batches/{id}` | 架次详情 |
| PUT | `/api/batches/{id}` | 更新元数据（不可变字段：batch_id/path/created_at 等） |
| DELETE | `/api/batches/{id}` | 删除登记（不删原始文件，自动发现架次加入忽略列表） |
| GET | `/api/batches/{id}/images` | 图片列表（分页 + 排序） |
| GET | `/api/batches/{id}/images/{file}/preview` | 缩略图/中图/原图预览 |
| POST | `/api/batches/scan` | 路径预检扫描（表单"扫描"按钮） |

### 2.4 前端改造

- 新建 `frontend/src/api/batches.ts` API 客户端（参考 `models.ts` 模式）。
- 3 个视图替换 mock：列表页（真实统计 + 删除）、新建页（真实路径扫描 + 提交）、详情页（内联编辑 + 分页图片浏览 + Lightbox）。
- mock 清理：从 `stores/mock.ts` 与 `api/mock.ts` 移除 batches 相关内容；同步更新引用 mock batches 的 `Index.vue`、`TaskNew.vue`。

### 2.5 边界处理

- **路径处理**：相对路径存相对形式（相对 PROJECT_ROOT），绝对路径保留原样；读取时统一 `Path.resolve()`。
- **.gitignore**：保持 `data/` 忽略规则，`batches.yaml` 为各环境本机配置，不纳入版本控制，启动时自动生成。

## 五、经验总结

1. **参考既有模式可显著降低重构风险**：`BatchRegistry` 完全复用 `ModelRegistry` 的 YAML 持久化、`_InlineList` flow_style、`_ordered_config` 字段排序等成熟设计，前后端风格统一，维护心智成本低。
2. **分页 + 动态缩略图是图片密集场景的合理组合**：内存索引避免反复磁盘扫描，400px 缩略图 + 懒加载保证 50 张/页流畅，1920px 中图用于 Lightbox 兼顾清晰度与带宽。
3. **忽略列表机制解决"自动扫描 vs 手动删除"冲突**：自动扫描注册的架次被删除后，若不记录忽略列表会在重启时被重新注册；`ignored_folders` 优雅解决该问题。
4. **环境差异需尽早暴露**：本次开发在 Python 3.11 验证通过，但 `uav-vis` 为 3.8，内置泛型注解（PEP 585）导致 import 崩溃。多环境项目应在最低版本环境做启动冒烟测试（详见 Bug 报告 #007）。
