## 一、需求背景

算法管理模块与作物检测模块在前期开发中遗留以下问题需要优化：

1. **无用字段冗余**：模型配置中存在 `FP16 (half)` 字段，但实际推理流程未使用该参数，属于无效配置项，需要从前后端及配置文件中彻底移除。
2. **模型注册无持久化**：原模型注册功能仅在内存中添加配置，重启服务后注册的模型丢失，且不支持权重文件上传，需要实现注册后自动写入 `config/models.yaml` 并保存权重文件到 `models/` 目录。
3. **命名风格不统一**：模型注册表单占位词命名风格与 `config/models.yaml` 中现有模型（如 `yolo12s-sugarcane`）不一致，需要对齐为 kebab-case 命名规范。
4. **模型图标不统一**：算法管理列表中模型图标为文字徽标，视觉风格不统一，需要替换为与项目现有 `fi-seedling.svg` 一致的绿色幼苗SVG图标。

## 二、方案设计

### 2.1 FP16 字段清理方案

通过"后端配置→API接口→前端类型→页面展示"的链路自上而下清理，确保无残留引用：

| 层级 | 清理内容 |
|------|----------|
| 配置层 | `config/models.yaml` 中所有模型删除 `half: false` 字段 |
| 注册中心 | `backend/core/registry.py` 移除 half 字段相关默认值与处理逻辑 |
| API 类型 | `frontend/src/api/models.ts` 的 `ModelConfig` 接口删除 `half: boolean` |
| 状态管理 | `frontend/src/stores/model.ts` 注册逻辑不再构造 half 参数 |
| 检测页 | `frontend/src/views/algo/Detect.vue` 移除 FP16 下拉选择控件 |
| 详情/注册页 | `ModelDetail.vue`、`ModelRegister.vue` 移除 half 字段的展示与输入控件 |

### 2.2 模型注册持久化方案

**后端核心改动**：

- `ModelRegistry` 新增 `save_to_yaml()` 方法，按标准字段顺序（`_MODEL_FIELD_ORDER`）序列化配置到 YAML 文件，`classes` 列表使用内联 flow 风格（`["Class1", "Class2"]`）保持与原有格式一致。
- `register()` 方法新增 `weight_file_path` 参数：接收已上传的临时权重文件路径，按模型名自动重命名（连字符 `-` 转下划线 `_`，加 `.pt` 后缀），移动到 `models/` 目录，并在配置中设置正确的 `weight` 相对路径。
- `backend/api/models_api.py` 的 `/api/models/load` 接口从接收 JSON 改为接收 `multipart/form-data`，支持 `weight_file` 文件字段上传；使用 `tempfile.mkstemp` 保存上传文件到临时路径，注册成功后由 registry 移动到正式目录；增加模型名称唯一性校验，防止重名覆盖。
- `backend/config.py` 启动时自动创建 `MODELS_DIR` 目录。
- `backend/app.py` 配置 `MAX_CONTENT_LENGTH = 500MB` 限制上传文件大小。

**前端核心改动**：

- `RegisterModelForm` 接口新增 `weight_file: File | null` 字段。
- `modelsApi.register()` 接收 `FormData`，不手动设置 `Content-Type`，让浏览器自动生成 multipart boundary。
- `model.ts` 的 `registerModel()` 将表单字段与文件 append 到 FormData 后发送。

### 2.3 文件上传交互设计

`ModelRegister.vue` 新增拖拽上传区域：

- 点击或拖拽 `.pt/.pth/.onnx` 权重文件到 dropzone 区域；
- 文件选中后显示文件名与大小；
- 支持清除已选文件重新选择；
- 自动从文件名推导模型名（如上传 `yolo12s-sugarcane.pt` 自动填充 name 为 `yolo12s-sugarcane`）。

### 2.4 图标统一方案

采用**内联 SVG** 方式直接嵌入幼苗图标路径，避免外部文件依赖与加载时机问题：

- SVG 路径参考 `frontend/assets/fi-seedling.svg`（植物/幼苗主题）；
- 激活状态（`is_active=true`）描边色为品牌绿 `#10B981`（Emerald-500）；
- 非激活状态描边色为灰色 `#9CA3AF`（Gray-400）；
- 模型列表表格首列、模型详情页页头图标统一替换。

## 五、经验总结

1. **无用字段应及时清理**：未使用的配置字段（如 `half`）会增加前后端类型维护成本与用户理解负担，需求变更后应同步清理配置层→接口层→展示层的整条链路。
2. **文件上传避免手动设置 Content-Type**：使用 `multipart/form-data` 时，浏览器需要自动生成 `boundary` 参数，手动设置 Content-Type 会导致 boundary 缺失、后端解析失败。
3. **YAML 输出格式一致性**：动态写入 YAML 时需定义字段顺序常量，使用 `sort_keys=False` 保持顺序；列表字段可通过自定义 representer 控制 flow/block 风格，保证与手工编辑的格式一致。
4. **内联 SVG 优于外部图标文件**：对于需要动态颜色控制（激活/非激活状态）的小图标，使用内联 SVG + stroke 颜色绑定比 img 标签引用外部 SVG 更灵活，避免 CSS currentColor 在跨文件使用时的作用域问题。
5. **文件名安全处理**：用户上传的文件名需经过 sanitize（过滤特殊字符），并按系统规则重命名存储，防止路径遍历攻击与文件覆盖风险。
