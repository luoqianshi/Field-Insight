## 二、方案设计

### 2.1 导航可折叠 + 拖拽调宽
在 `Sidebar.vue` 内维护 `collapsed`（折叠到 56px 图标列）与 `width`（200~360px）两个响应式状态，`watch` 持久化到 `localStorage[uav_vis_sidebar_state]`。右侧新增 4px 拖拽手柄，`mousedown` 后监听 `mousemove` 计算新宽度并 clamp 到 `[200, 360]`。`AppLayout` 使用 flex 布局，侧栏宽度变化时 `main` 自动伸缩，无需改动。

### 2.2 检测/计数上传图片持久化
根因：`previewUrl` 来自 `URL.createObjectURL(file)`，在 `onBeforeUnmount` 被 `revokeObjectURL` 释放；而 Pinia store 只持有结果图（base64）。方案：把 `originalFile: shallowRef<File|null>` 提升到 store，页面用 `watchEffect` 派生出新的 object URL（离开页面 revoke，回到页面自动重建），仅用户主动「清除」或切换本机路径时才清空。

### 2.3 数据处理 · 新建任务
- 输入源类型由 2 种扩为 3 种：架次选择 / **数据选择（新增）** / 自定义目录路径。数据选择直接调用已有 `GET /api/processing/processed` 列出 `output/` 下加工产物，选中项把 `output/{task_id}` 作为 `input_paths` 提交（后端 `_collect_inputs` 已支持任意目录扫描）。
- 自定义路径、输出路径均增加「选择」按钮，复用 `POST /api/batches/pick-folder`（tkinter 弹窗）。
- 调整默认值：任务名「CLAHE 增强」「滑窗裁切」、`overlap_ratio=0.05`、输出路径默认 `output/`。

### 2.4 任务详情预览按方法差异化
移除原来的「缩略图网格 / 原图对比」双 tab，改为按 `task_type` 渲染：
- **CLAHE**：单张大图对比（原图 vs 增强后），可点击 `ImageViewer` 放大。
- **Crop**：第一张 tile（`_tile_0001_x0_y0` 作代理预览）+ 该原图 stem 对应的所有 tile 缩略图网格。
- 后端 `list_task_files` 新增可选 `?filename_prefix=` 过滤，用于取某原图对应的全部 tile。

### 2.5 加工数据详情
- 头部新增真实「输出路径：`output/{task_id}/`」展示。
- 图片渐进式加载：每页 36 张，滚动/点击「加载更多」追加，直到全部加载，移除 80 张限制。
- 每张缩略图 `@click` 打开 `ImageViewer`（original 尺寸）放大。

## 五、经验总结

1. **object URL 生命周期与 SPA 导航**：`URL.createObjectURL/file` 的 object URL 在组件卸载时被 revoke 会导致"离开页面图片消失"。正确做法是把源文件（`File`）提升到 store，页面以 `watchEffect` 派生 object URL，卸载时只 revoke 当前 URL，返回时自动重建。
2. **进度限制的渐进式加载**：一次性 `page_size=50 或 80` 会因后端 `max 200` 上限与前端手写限制造成"只能看 80 张"。统一用"页码 + totalPages + 追加合并"模式（参照已有 `BatchDetail.vue`）。
3. **结果预览按处理类型差异化**：不同处理方法（CLAHE 对比 vs 滑窗分块）的"结果可视化"语义不同，不应共用统一网格/对比模板。数据源也不一致——Crop 的 output 目录只有 tile，原图不在其中，需用 `_tile_0001_x0_y0` 作代理或保留原图路径。
4. **后端参数向后兼容**：为既有接口新增可选查询参数（`filename_prefix`）即可满足前端新场景，无需破坏旧调用；类型定义同步更新避免 TS 报错。
5. **弹窗选路径复用**：`POST /api/batches/pick-folder`（tkinter）已封装系统文件夹选择，可跨模块复用，避免重复实现。
