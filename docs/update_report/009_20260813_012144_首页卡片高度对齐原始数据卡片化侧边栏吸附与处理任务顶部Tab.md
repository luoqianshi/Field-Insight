## 一、需求背景

用户基于 4 张示意图提出 4 项 UI 更新需求：

1. **图一（首页）**：首页【快速入口】与【最近活动】两个矩形框高度需对齐，与红框绘制高度一致。
2. **图二（原始飞行数据）**：【原始飞行数据总览】需用单独的卡片分别展示每个数据（参考加工数据模块的实现），并删除"作物类型"一项。
3. **图三（完整数据集查看）**：查看完整数据集向下滚动时，右侧导航栏应固定不动；其它有类似长内容的地方（如加工数据原始数据、数据管理多条架次表格）也应同步保持左侧导航固定。
4. **图四（处理任务）**：【CLAHE 增强】与【滑窗裁切】的任务执行表格应参考【算法广场】的处理方式，按顶部导航栏切换，一种处理方式独立成一部分。

## 二、方案设计

### 2.1 首页卡片高度对齐（图一）

- 沿用现有 `grid grid-cols-3` 布局，通过给网格列容器加 `items-stretch`，并让左右两个内容列及其内部卡片使用 `h-full flex flex-col` 链式撑满。
- "最近活动"列表与"暂无最近活动"占位加 `flex-1`，使左右两列高度由内容更高的"快速入口"决定，实现高度一致。
- 无需引入魔法数字或固定 `min-h-*`，响应式友好。

### 2.2 原始飞行数据总览卡片化（图二）

- 参考 `Processed.vue` 的 4 张独立卡片模式，将原来单卡片内 `grid grid-cols-4` 的四项指标改为 4 张独立 `bg-white border rounded-card` 卡片。
- 删除"作物类型"列及其对应 `primaryCrop` computed；保留 `crops` computed（仍用于检索栏"全部作物"下拉）。
- 4 卡内容：① 架次数、② 载入图片总数、③ 总大小（副标题 MIPI · 格式）、④ 主要分辨率（副标题格式）。
- 卡片统一加 `card-hover` 悬停样式，与加工数据 / 算法管理视觉一致。

### 2.3 侧边栏固定吸附（图三）

- 根因分析：全局 `styles.css` 中 `html, body { height: 100% }` 将 body 锁死在视口高度；flex 容器默认 `align-items: stretch` 会把 sidebar 撑满父容器高度，导致 `sticky top-0` 在长内容页滚到底部时失效。
- 方案：仅做最小改动——布局壳容器加 `items-start` + `<main>` 加 `min-w-0`；Sidebar 加 `self-start`（及 scoped `align-self: flex-start`）。
- 不修改 `styles.css` 的 `html, body { height: 100% }`，避免影响 Lightbox 等浮层依赖。

### 2.4 处理任务顶部 Tab 分区（图四）

- 采用"页面内 tab 切换"方案（不新增路由），复用 `styles.css` 中 `.sub-tab` 样式（与 `SubTabs.vue` / `DataSubTabs.vue` 一致）。
- 顶部新增 "CLAHE 增强" / "滑窗裁切" 两个 tab；`visibleGroups` 由 `filterType` 改为按 `tab` 过滤。
- 移除"全部类型"下拉（由 tab 承担），保留"全部状态"下拉。
- 数据加载改为一次性拉取全部任务，tab 切换走客户端过滤，保证副标题"累计 N 次执行"为全量计数。

## 五、经验总结

- **Sticky 在 flex 容器中失效的根因**：`align-items: stretch`（默认）会让 `sticky` 子项被撑满父级整高，`top:0` 便失去"吸顶"效果。解法是在父容器 `items-start` + 子项 `self-start`，并给内容列 `min-w-0` 防止溢出撑爆。
- **卡片高度对齐**：用 `grid items-stretch` + `h-full flex flex-col` + 内容容器 `flex-1` 的链式撑满方案，比硬编码 `min-h-*` 更响应式、更易维护，且不引入魔法数值。
- **顶部子标签一致性**：处理任务页复用全局 `.sub-tab` 样式，与算法广场 `SubTabs.vue`、数据管理 `DataSubTabs.vue` 视觉一致，形成统一的"页面级 Tab 导航"心智模型。
- **客户端过滤 vs 服务端过滤**：当副标题需要展示"累计 N 次"全量计数时，一次性拉取全量 + 客户端 tab 过滤，比每次切换都请求后端更简单、避免计数口径不一致。
