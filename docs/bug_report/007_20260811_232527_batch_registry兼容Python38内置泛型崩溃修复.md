# Bug 修复报告 #007

- **报告编号**：007
- **记录时间**：20260811_232527
- **问题标题**：batch_registry 兼容 Python 3.8 内置泛型语法崩溃
- **涉及模块**：`backend/core/batch_registry.py`
- **严重程度**：高（后端应用无法启动）
- **状态**：已修复并验证

---

## 一、问题现象

按 `python -m backend.app` 启动 Flask 后端（:5000）时，进程立即崩溃，抛出如下异常：

```
Traceback (most recent call last):
  File "...\backend\app.py", line 17, in <module>
    from api.health_api import health_bp
  File "...\backend\api\health_api.py", line 4, in <module>
    from core.engine import get_detector, get_registry
  File "...\backend\core\engine.py", line 13, in <module>
    from core.batch_registry import BatchRegistry
  File "...\backend\core\batch_registry.py", line 49, in <module>
    class BatchRegistry:
  File "...\backend\core\batch_registry.py", line 160, in BatchRegistry
    plot_name: Optional[str] = None) -> list[dict]:
TypeError: 'type' object is not subscriptable
```

报错发生在类定义阶段（注解求值），即 **import 阶段即崩溃**，后端 Web 服务完全无法启动。

## 二、排查过程

### 2.1 定位报错位置

异常栈指向 `core/batch_registry.py` 第 160 行的返回类型注解 `-> list[dict]`。该文件是本模块架次注册功能（数据管理真实化）新增的 `BatchRegistry` 类。

### 2.2 识别根因：内置泛型语法与 Python 版本不匹配

`list[dict]`、`dict[str, dict]`、`set[str]` 这种**内置类型下标泛型注解**（PEP 585）自 **Python 3.9** 才支持。当运行环境的 Python 版本低于 3.9 时，`list` 仍是普通 `type` 对象，对其下标（`list[...]`）会抛出 `TypeError: 'type' object is not subscriptable`。

本次开发环境（TraeAI sandbox）用 Anaconda base（Python 3.11）验证时 import 正常，但用户实际启动后端用的是 `uav-vis` conda 环境（Python 3.8），该环境不支持 PEP 585 语法，导致启动崩溃。

> **环境差异**：
> - 开发/CI 验证环境：Anaconda base，Python 3.11.5（PEP 585 可用）
> - 实际运行环境：`uav-vis` conda 环境，Python 3.8（PEP 585 不可用）

### 2.3 全量排查同类语法

对 `batch_registry.py` 全文检索内置泛型注解，发现共 5 处受影响：

| 行(原) | 原写法 | 问题 |
|--------|--------|------|
| 61 | `self._batches: dict[str, dict]` | 不支持 |
| 62 | `self._image_index: dict[str, list[dict]]` | 不支持 |
| 160 | `-> list[dict]` | 不支持 |
| 369 | `-> tuple[list[dict], int, int, list[str]]` | 不支持 |
| 410 | `-> List[Path]`（已用 typing，OK） | — |
| 63 | `self._ignored_folders: set[str]` | 不支持 |

## 三、解决方案

将 PEP 585 内置泛型改为 `typing` 模块的旧式别名（Python 3.8 兼容）：

1. 顶部导入补充 `Dict`、`List`：
   ```python
   from typing import Dict, List, Optional
   ```
2. 实例注解：
   - `self._batches: Dict[str, dict] = {}`
   - `self._image_index: Dict[str, List[dict]] = {}`
   - `self._ignored_folders: set = set()`
3. 方法返回注解：
   - `list_batches(...) -> List[dict]`
   - `_scan_images(...) -> tuple`（原复杂 tuple 注解简化为 `tuple`，避免连带嵌套泛型问题）
   - `_auto_discover_batches() -> List[Path]`（原本已是 typing，保持不变）

`Optional` 已从 `typing` 导入，无需改动。

## 五、经验教训

1. **内置泛型注解（PEP 585）有 Python 版本门槛**：`list[T]`、`dict[K, V]`、`set[T]` 需 Python ≥ 3.9。写带注解的公共代码时，应先确认目标运行环境版本，或统一使用 `typing.List` / `typing.Dict` 等旧式别名以保证最大兼容。
2. **"开发环境编译通过 ≠ 生产可运行"**：本次正是 Anaconda base（3.11）验证通过、但 `uav-vis`（3.8）启动崩溃。多环境项目应明确每个环境的最低 Python 版本，并在最小版本上做启动冒烟测试。
3. **import 期注解求值最危险**：类/函数定义处的注解在 import 时即求值，语法不兼容会直接阻断整个模块加载，进而拖垮整个应用启动。这类问题应尽早通过最小环境冒烟测试暴露。
