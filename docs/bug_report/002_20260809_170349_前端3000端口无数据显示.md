# Bug 修复报告 #002

- **报告编号**：002
- **记录时间**：20260809_170349
- **问题标题**：访问前端 `localhost:3000` 只见空数据静态页，仅 `:5000` 有真实数据
- **涉及模块**：`frontend/vite.config.ts`、`frontend/src/api/client.ts`、`backend/app.py`、`backend/config.py`、`start.ps1`
- **严重程度**：低（架构理解/环境问题，非代码缺陷）
- **状态**：已定位并说明（非代码修复，属运行方式问题）

---

## 一、问题现象

用户反馈：访问前端 `http://localhost:3000/` 时，看到的是**没有后端数据的纯前端静态页面**；只有访问 Flask 启动的 `http://127.0.0.1:5000` 或 `http://10.125.62.219:5000`，才能看到带真实数据的完整前端页面。用户询问这是否正常，以及如何让 `:3000` 也能正常显示数据。

## 二、排查过程

### 2.1 梳理前后端连接架构

读取关键配置文件，确认本项目采用「开发期前后端分离 + 生产期单端口托管」的双模式架构：

| 文件 | 关键配置 | 作用 |
|------|---------|------|
| `frontend/vite.config.ts` L14-22 | `server.port: 3000`；`proxy['/api'] → http://localhost:5000` | 开发期 Vite :3000，`/api` 代理到 Flask :5000 |
| `frontend/vite.config.ts` L23-26 | `build.outDir: '../backend/static'` | 生产构建产物落入后端静态目录 |
| `frontend/src/api/client.ts` L4-6 | axios `baseURL: '/api'` | 前端统一以相对路径 `/api` 请求，由代理转发 |
| `backend/config.py` L14-16 | Flask 监听 `0.0.0.0:5000`，`DEBUG=True` | 后端地址，局域网 IP 亦可访问 |
| `backend/app.py` L66-81 | `serve_spa` 非 `/api` 请求回退 `index.html` | 生产模式单端口提供 API + 静态资源 |
| `start.ps1` L82 | 仅 `python -m backend.app` | 一键启动**不拉起 Vite dev server** |

### 2.2 定位根因

`start.ps1` 一键启动脚本最后只执行了 `python -m backend.app`（L82），**没有启动 Vite dev server（:3000）**。因此：

- `:5000` 由 Flask 提供服务，同时托管了 `backend/static/` 里的前端构建产物 **和** 后端 API，同源（same origin），数据完整。
- `:3000` 若在运行，只能是残留的 Vite dev server 进程；其 `/api` 代理目标写死为 `http://localhost:5000`（`vite.config.ts` L18）。当 Flask 未在 `localhost:5000` 监听（或仅暴露于局域网 IP）时，代理不可达，前端渲染出空数据。

结论：**这不是代码缺陷，而是运行方式/环境问题**。`:3000` 空数据根因是「Vite dev server 在跑，但其代理的后端 `localhost:5000` 不可达」。

## 三、解决方案

针对不同场景给出三种方案：

### 方案 1（推荐·本地开发）：同时启动前后端

分别启动 Flask 与 Vite dev server，`/api` 经代理转发到 :5000：

```powershell
# 终端 1：启动后端
python -m backend.app

# 终端 2：启动前端 dev server
cd frontend
npm run dev
```

此后访问 `http://localhost:3000` 即有数据且带 HMR。

### 方案 2（Flask 暴露于局域网 IP 时）：调整代理目标

若 Flask 仅暴露于 `10.125.62.219:5000`，修改 `frontend/vite.config.ts` L18：

```ts
proxy: {
  '/api': {
    target: 'http://10.125.62.219:5000',   // 改成 Flask 实际地址
    changeOrigin: true,
  },
},
```

### 方案 3（可选·一键开发环境）：新增 `dev.ps1`

在项目根目录新增脚本，一条命令拉起「Vite :3000 + Flask :5000」：

```powershell
# 启动 Flask（后台）
Start-Process python -ArgumentList "-m","backend.app"
# 启动 Vite dev（前台）
Push-Location "$PSScriptRoot/frontend"
npm run dev
Pop-Location
```

## 四、验证结果

| 环境 | 操作 | 结果 |
|------|------|------|
| 本地 `:5000` | 访问 `http://127.0.0.1:5000` / `http://10.125.62.219:5000` | 前端页面 + 真实数据正常 |
| 本地 `:3000` | 仅 Flask 运行、Vite 代理目标不可达 | 页面壳正常，数据为空（复现问题） |
| 本地 `:3000` | Flask(:5000) + Vite(:3000) 同时运行，代理可达 | 数据正常（理论验证，方案 1） |

> 注：本次为架构/运行方式说明，未涉及代码改动，故无降级/完整环境对比测试；方案 1 的并发启动为该架构的标准开发范式。

## 五、经验教训

1. **Vite + Flask 全栈项目存在两种运行模式**：开发期双进程（Vite :3000 代理 `/api` → Flask :5000），生产期单进程（Flask :5000 单端口托管）。判断「哪个端口没数据」前，先确认当前命中的是哪个进程。
2. **一键启动脚本只启动后端属于正常设计**：`start.ps1` 面向生产演示，直接 `npm run build` + 起 Flask，`:5000` 才是权威入口；`:3000` 需要额外手动开启 Vite。
3. **代理目标写死 localhost 的坑**：Vite `proxy.target` 为 `http://localhost:5000`，当 Flask 只暴露于局域网 IP 时，需同步修改 target，否则代理不可达。
4. **同源 vs 跨源的数据差异**：`:5000` 数据完整是因为前端静态资源与 API 同源；跨端口时依赖代理，代理一旦失效即表现为「有页面无数据」。
