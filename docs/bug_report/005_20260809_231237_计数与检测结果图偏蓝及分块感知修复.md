## 一、问题现象

1. **作物计数结果图整体偏蓝**：执行"检测与计数"后，返回的标注图中检测框呈现蓝色，且图像内容颜色失真（偏红的土壤/植被变蓝调，整体偏冷色）。
2. **单图检测（非计数）结果**：框色同样偏蓝（同源 bug），但图色正常。
3. **用户怀疑"未进行分块处理"**：实际测试后感觉不像有滑窗子块处理，无法判断是否真的对整图做了切块再映射。

### 2.2 偏蓝根因定位：通道顺序不匹配

颜色流转追踪 `_draw`（counter.py L105-121 修复前）：

1. `img = image.copy()` → **RGB**（因 L32 已 BGR→RGB）
2. `cv2.rectangle(img, ..., (229, 57, 53), 2)` → 元组写入 RGB 数组 = **红**（本意正确）
3. `cv2.imencode(".jpg", img)` → **BUG**：`imencode` 期望 **BGR**，但 `img` 是 **RGB**，R/B 通道被对调编码

**结果**：红色框 `(229,57,53)` 编码后变 **蓝**；图像内容红↔蓝对调，整图偏冷色。

### 2.3 同源 bug：检测页框色

[detector.py:119-135](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/detector.py#L119-L135) 修复前：`cv2.imread(path)` 得 **BGR**，但颜色元组 `(229,57,53)` 按 RGB 红书写，在 BGR 数组里实为 (B=229,G=57,R=53)=**蓝**。故检测页图色正常但框是蓝色。

> 计数链路调用 `detector.detect(tile, draw=False)` 不触发 `_draw`，故计数偏蓝仅由 counter.py 的 `_draw` 负责。

### 2.4 "感觉没分块"的真实原因

[tiling.py:7-13](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/tiling.py#L7-L13)：

```python
def calc_starts(length):
    if length <= tile_size:
        return [0]   # ← 维度 ≤ tile_size 时只返回 1 个起点
```

当原图**两维度均 ≤ tile_size（默认640）** 时，仅生成 1 个 tile（整图送检），`tile_count=1`，等价于未分块；且输出图不画 tile 边界，用户视觉上无法感知分块是否发生。

## 三、解决方案

### 3.1 修复 counter.py 偏色

[counter.py `_draw`](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/counter.py#L105-L125)：

```python
img = cv2.cvtColor(image, cv2.COLOR_RGB2BGR)  # RGB → BGR
...
cv2.rectangle(img, (x1, y1), (x2, y2), (53, 57, 229), 2)  # BGR: 红
cv2.putText(img, str(d["id"]), (x1, y1 - 5), cv2.FONT_HERSHEY_SIMPLEX, 0.5, (53, 57, 229), 1)
```

- 编码前先 `RGB→BGR`，`imencode` 即得正确图像内容；
- 颜色元组改 BGR 红 `(53,57,229)`，框为红色。

### 3.2 修复 detector.py 同源偏色

[detector.py `_draw`](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/backend/core/detector.py#L119-L144)：统一"先到 BGR 再绘制+编码"。

```python
if isinstance(image, str):
    img = cv2.imread(image)          # BGR
elif image.ndim == 3:
    img = cv2.cvtColor(image, cv2.COLOR_RGB2BGR)  # RGB → BGR
else:
    img = image.copy()
...
cv2.rectangle(img, (x1, y1), (x2, y2), (53, 57, 229), 2)  # BGR: 红
```

路径入参（detect_api 均传路径）得 BGR，数组入参（如未来计数 draw=True 传 RGB tile）先转 BGR，两条绘制链路统一为 BGR 约定。

### 3.3 前端增加分块未触发提示

[Counting.vue L643-654](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/frontend/src/views/algo/Counting.vue#L643-L654)：当 `tile_count === 1` 时显示琥珀色提示条，说明"原图尺寸未超过 tile_size，整图作为单块送检，未触发滑窗分块"，并建议换大图或调小 tile_size。使用 `params_snapshot.tile_size` 保证历史回看准确。

## 五、经验教训

1. **cv2 通道约定陷阱**：`cv2.imread` 返回 BGR，`cv2.imencode/imwrite` 也期望 BGR；一旦在链路中做了 `cvtColor(BGR2RGB)`，编码前必须转回 BGR，否则 R/B 对调导致偏色。统一约定为"绘制与编码一律在 BGR 下进行"。
2. **颜色元组顺序**：写 `cv2.rectangle`/`putText` 颜色时，需与当前数组通道顺序匹配。BGR 数组下红色是 `(53,57,229)` 而非 `(229,57,53)`（后者是蓝），建议带 `# BGR: 红` 注释提升可读性。
3. **分块是否生效的判断依据**：不要靠肉眼或"感觉"，应以结果中的 `tile_count` 为准。原图维度 ≤ tile_size 时滑窗退化为单块是预期行为，不是 bug。
4. **复用性问题**：两个绘制方法存在同源 bug，修一处时需同步排查另一处，避免两链路颜色不一致。
