# Bug 修复报告 #008

- **报告编号**：008
- **记录时间**：20260812_225927
- **问题标题**：数据处理CLAHE增强无法触发及UI多项交互与视觉修复
- **涉及模块**：backend/core/processing_engine.py、backend/core/processing_registry.py、frontend/src/views/process/、frontend/src/components/layout/、frontend/src/views/index/
- **严重程度**：高
- **状态**：已修复并验证

---

## 一、问题现象

本次共修复7个问题，分为功能缺陷和UI体验两类：

### 功能缺陷
1. **CLAHE增强无法正常触发**：在【数据处理】选择CLAHE增强时，选择已经过CLAHE增强加工过的数据集，或选择裁切后的数据集作为输入，都无法正常启动数据增强操作（任务提交后无图片被处理）。
2. **默认任务名过于简略**：新建数据处理任务时，默认任务名固定为「CLAHE 增强」，无法区分不同批次的任务。

### UI体验问题
3. **任务详情页存在无效按钮**：查看任务详情页面右上角有「导出数据」与「重新运行」按钮，但没有实际功能实现。
4. **侧边导航栏高度静态固定**：侧边栏使用固定高度`h-screen`，当页面内容增长时侧边栏长度不足，底部导航项被截断。
5. **侧边栏收起按钮位置不合理**：收起/展开按钮放在侧边栏最底部，不符合常规交互直觉。
6. **首页图标混用Font Awesome**：首页功能卡片仍使用Font Awesome图标，与项目自定义SVG图标体系不统一。
7. **处理任务配色混乱**：数据处理页面不同类型任务使用彩色标签区分，视觉过于花哨，缺乏克制。

## 二、排查过程

### 2.1 CLAHE增强无法触发的根因定位
- 复现路径：新建CLAHE增强任务 → 选择已处理过的数据集目录 → 提交任务 → 观察到任务状态显示running但processed_images始终为0
- 检查后端`processing_engine.py`的`_collect_inputs()`方法，发现原逻辑只扫描输入根目录下的图片，不会递归进入子目录
- 检查经过CLAHE增强或滑窗裁切后的产物目录结构，发现图片实际存储在子目录中（如`clahe_output/`、`crops/`），并通过`index.json`记录子目录信息
- 同样的问题存在于`processing_registry.py`的`_count_input_images()`计数方法，导致提交时图片计数为0

### 2.2 UI问题定位
- 检查Sidebar.vue的CSS布局，发现使用了`h-screen`固定高度，且flex布局未正确配置滚动区域
- 检查TaskDetail.vue模板，确认两个按钮确实只有UI没有绑定事件处理函数
- 检查首页Index.vue图标使用，确认混用了`<i class="fa-solid ...">`和项目自定义的`<Icon>`组件
- 检查Tasks.vue/TaskNew.vue/TaskDetail.vue的类型标签，确认使用了`tag-blue`、`tag-amber`等彩色类

## 三、解决方案

### 问题1：CLAHE增强输入源递归扫描修复
修改后端两个核心文件，支持递归扫描和index.json解析：
- **processing_engine.py**：重写`_collect_inputs()`方法，新增递归子目录扫描逻辑，优先读取index.json中的sub_dirs配置，否则递归遍历所有子目录查找图片
- **processing_registry.py**：同步修复`_count_input_images()`方法，使其与扫描逻辑保持一致，正确统计子目录中的图片数量

### 问题2：默认任务名格式更新
在`TaskNew.vue`中添加`generateDefaultName()`函数：
- 格式为`类型名_YYYYMMDD_HHMMSS`，例如`CLAHE增强_20260812_225927`、`滑窗裁切_20260812_225927`
- 在切换处理类型时自动更新默认任务名

### 问题3：移除无效按钮
在`TaskDetail.vue`页面头部：
- 移除「导出数据」和「重新运行」两个无功能按钮
- 添加「返回列表」router-link按钮，提供明确的返回路径

### 问题4-5：侧边栏布局与收起按钮修复
- **AppLayout.vue**：将布局容器从`h-screen`改为`min-h-screen`，支持页面高度增长
- **Sidebar.vue**：重构flex布局结构：
  - 顶部区域：Logo + 收起按钮（从底部移至顶部logo右侧）
  - 中间导航区域：添加`overflow-y-auto`，内容超出时自动滚动
  - 底部区域：保留用户信息区域
- 确保页面内容增长时侧边栏始终铺满视口高度，导航项过多时可滚动查看

### 问题6：首页图标统一
修改`Index.vue`：
- 将所有Font Awesome图标（`<i class="fa-solid fa-xxx">`）替换为项目自定义的`<Icon>`组件
- 图标映射：folder-open→dataset、wand-magic-sparkles→augment、database→database、microchip→chip、chart-column→chart、gears→settings等
- 保持图标尺寸和颜色风格统一

### 问题7：处理任务配色统一
修改Tasks.vue、TaskNew.vue、TaskDetail.vue三个文件：
- 移除类型标签的彩色类（tag-blue、tag-amber），统一使用默认中性灰色`.tag`样式
- 分组图标背景统一使用品牌色浅色调（bg-brand-50 text-brand-700），不再按类型区分颜色
- 统计数字中的「进行中」也从琥珀色改为中性灰色，保持视觉克制

## 五、经验教训

1. **文件系统操作需考虑嵌套目录**：处理用户输入数据集时，必须考虑到处理产物会存放在子目录中，扫描逻辑不能只看根目录，应支持递归遍历或读取index.json元数据。
2. **UI按钮必须绑定实际功能**：没有实现的功能按钮不应提前放入页面，避免误导用户。若需要占位应明确标注「即将上线」或禁用状态。
3. **布局优先使用min-h-screen而非h-screen**：后台管理系统页面内容长度通常不固定，侧边栏和主容器应使用`min-h-screen`配合flex布局，确保内容增长时布局不被破坏。
4. **图标体系保持统一**：项目自定义了SVG Icon组件后，应完成全量迁移，避免Font Awesome和自定义图标混用造成视觉不一致。
5. **配色保持克制**：企业级/工具类后台系统，功能标签优先使用中性色，仅用颜色区分状态（成功/失败/进行中），而非区分功能类型，避免视觉噪音。
