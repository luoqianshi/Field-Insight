- **报告编号**：009

- **涉及模块**：frontend 布局（AppLayout.vue / Sidebar.vue）

## 一、问题现象

当右侧主内容区内容超出视口高度、向下滚动时，左侧侧边栏会跟随页面一起上移：顶部 Logo/导航被滚出屏幕，底部露出右侧 `main` 的灰色背景，形成"侧边栏悬空"的观感。侧边栏没有像预期那样固定在视口内。

截图位置（浏览器实测留存）：`c:\Users\lqs\AppData\Local\Temp\trae\screenshots\batches-scrolled-bottom.png` 等。

## 二、排查过程

### 2.1 布局结构梳理

`AppLayout.vue` 原始结构（改动前）：

```
<div class="flex min-h-screen w-full items-start">
  <Sidebar />
  <main class="flex-1 min-h-screen p-8 bg-surface-bg/30 min-w-0">…</main>
</div>
```

外层容器高度随内容撑开，`main` 内容多长页面就多长，**滚动发生在 window（document）级**，而非某个内部容器。

侧边栏 [Sidebar.vue](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/frontend/src/components/layout/Sidebar.vue) 的 `<aside>` 类为 `h-screen … sticky top-0 self-start …`，意图用 `position: sticky` 让侧边栏在页面滚动时吸顶固定。

### 2.2 根因定位：sticky 被 scoped 样式覆盖

同一文件 scoped 样式中存在：

```css
.sidebar {
  position: relative;   /* ← 覆盖了 Tailwind 的 sticky */
  align-self: flex-start;
  transition: width 0.2s ease-out;
  overflow: hidden;
}
```

- Vue scoped 样式会编译为 `.sidebar[data-v-xxx]`，选择器优先级 = 0,2,0。
- Tailwind 的 `.sticky` 优先级 = 0,1,0。
- 因此 `.sidebar` 里的 `position: relative` 以更高优先级覆盖了 `sticky`，`position: sticky` 完全失效。

结果：侧边栏实际是文档顶部一个普通的 100vh 块（`position: relative`），并不吸顶。文档下滚时它一起上移，顶部被裁掉、底部露出 `main` 的灰底——即截图中的悬空现象。

### 2.3 影响面评估

- 全项目检索无任何依赖 window 滚动位置的 JS（无 `window.scrollTo` / `scrollIntoView` / `onscroll` / `@scroll`），可安全迁移滚动容器。
- 视图内的局部 sticky（`TaskNew/BatchNew/DatasetNew/ModelRegister` 的 `sticky top-5` 摘要卡、`Detect` 的 `sticky top-0` 表头）随滚动容器改为 `main` 后会自动相对 `main` 生效，行为不变。
- 全局 `::-webkit-scrollbar` 样式已存在，main 内部滚动条外观一致。

## 三、解决方案

采用**独立滚动容器**方案：外层容器固定视口高度并禁止 window 滚动，滚动条移入 `main` 内部。侧边栏因此天然全局固定，不依赖 sticky 链条的正确性，比单纯修 sticky 覆盖更彻底。

### 3.1 `frontend/src/components/layout/AppLayout.vue`

```diff
-  <div class="flex min-h-screen w-full items-start">
-    <main class="flex-1 min-h-screen p-8 bg-surface-bg/30 min-w-0">
+  <div class="flex h-screen w-full overflow-hidden">
+    <main class="flex-1 h-full min-h-0 overflow-y-auto p-8 bg-surface-bg/30 min-w-0">
```

- 外层：`min-h-screen items-start` → `h-screen overflow-hidden`（固定视口高度，禁止 window 滚动）。
- main：`min-h-screen` → `h-full min-h-0 overflow-y-auto`（成为唯一滚动容器）。
- 同步更新注释为"左侧 Sidebar 固定全高 + 右侧主内容区独立滚动"。

### 3.2 `frontend/src/components/layout/Sidebar.vue`

- `<aside>` 类中删除失效的 `sticky top-0 self-start`（新布局下不再需要）。
- scoped 样式清理：
  - `.sidebar` 删除 `align-self: flex-start`；保留 `position: relative`（拖拽手柄 `.sidebar-resize-handle` 的 absolute 定位需要它，且不再与 sticky 冲突）。
  - 删除空的重复规则 `.sidebar--collapsed { transition: width 0.2s ease-out; }`（与 `.sidebar` 重复）。

## 五、经验教训

1. **`position: sticky` 极易被覆盖**：Vue scoped 样式带 `[data-v-xxx]`，其 `position: relative` 优先级高于 Tailwind 的 `.sticky`（0,2,0 > 0,1,0）。混用 Tailwind 与手写 scoped 定位时务必检查优先级，或避免在自带定位属性的自定义类里重复声明 `position`。
2. **滚动方案选型**：需要"左侧全局固定 + 右侧独立滚动"时，独立滚动容器（外层 `h-screen overflow-hidden` + 内容 `overflow-y-auto`）比依赖 sticky 更稳，且天然免疫 sticky 覆盖问题；改前先检索是否依赖 window 滚动位置，避免副作用。
3. **残留代码要清理**：失效的 `sticky` 类与重复的空 scoped 规则属修复过程中可一并清除的冗余，防止后续误导。
