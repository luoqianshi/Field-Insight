## 一、问题现象

数据集详情页（`/dataset/datasets/:id`）"统计分析报告"卡片中，统计文字（"N 个类别"、"平均尺寸 W × H px"、"共 X 图 / Y 框"等模板插值）正常显示，但三个 ECharts 图表区域（类别分布柱状图、标注框面积分布直方图、目标尺度分布堆叠条）始终为空白 div，无任何图形，控制台也无报错。

### 2.2 根因定位：前端图表初始化时机 Bug

关键时序（`DatasetDetail.vue`）：

1. 模板为三段式条件渲染：`v-if="loading"`（307 行）/ `v-else-if="errorMsg && !dataset"` / `v-else-if="dataset"`（318 行）。三个图表容器（479/491/503 行）位于第三个分支内。
2. `loadDataset()`（121–134 行）中 `await loadReport()` 在 `finally { loading.value = false }` **之前**执行。
3. `loadReport()` 原实现：赋值 `report.value` 后 `await nextTick(); renderCharts()`。此刻 `loading === true`，图表容器不在 DOM 中，`classChartRef/areaChartRef/sizeChartRef` 全为 `null`，`renderCharts()` 内三个 `if (xxxRef.value)` 守卫**静默跳过**，ECharts 从未初始化。
4. 随后 `loading=false` 容器挂载，文字插值正常显示，但全文件无 `watch`，`renderCharts` 仅此一次调用，图表永远空白。

佐证：点击"重新生成"按钮（此时 `loading` 已为 false）可正常出图——与根因完全吻合。

## 三、解决方案

修改 `frontend/src/views/dataset/DatasetDetail.vue`，采用 watch 声明式兜底：

1. 引入 `watch`（第 6 行 import）。
2. `loadReport()` 中移除 `await nextTick(); renderCharts()` 即时渲染，仅赋值 `report.value = res.data`。
3. 新增 `watch([loading, report], ...)`：当 `loading=false` 且报告数据就绪时，`nextTick` 后统一调用 `renderCharts()`。

```ts
// 图表容器位于 v-else-if="dataset" 分支内，仅当 loading=false 后才挂载；
// 首次加载时 loadReport 先于 loading=false 完成，故在此统一补渲染。
watch([loading, report], async ([isLoading, rep]) => {
  if (!isLoading && rep) {
    await nextTick()
    renderCharts()
  }
})
```

覆盖路径：首次进入页面（`loadReport` 先完成但跳过 → `finally` 置 `loading=false` → watch 触发渲染）、点击"重新生成"（`report` 变化 → 重新渲染）、加载失败重试（同首次路径）。

## 五、经验教训

1. **ECharts（及 canvas 类图表）初始化必须以容器真实挂载为前提**：Vue 中若图表容器处于 `v-if` 条件分支内，且初始化发生在分支渲染之前，`ref` 为 `null`，`if (ref.value)` 守卫会静默跳过、无任何报错——这种"静默空白"比报错更难排查。
2. **用 `watch` 驱动图表渲染而非在异步加载函数内直接渲染**：加载时序（loading 状态翻转）与 DOM 挂载时机强相关，声明式 watch 能覆盖所有路径，避免时序假设。
3. **排查"文字正常、图表空白"类问题时，先区分数据层与渲染层**：先核验后端返回与前后端契约（本次数据完全正常），再聚焦渲染时机，避免在后端反复折腾。
