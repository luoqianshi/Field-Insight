# Bug 修复报告 #004

- **报告编号**：004
- **记录时间**：20260809_202933
- **问题标题**：前端导航栏点【数据集管理】时【数据管理】被连带高亮
- **涉及模块**：`frontend/src/components/layout/Sidebar.vue`
- **严重程度**：中（纯前端展示异常，不影响功能，但误导用户当前所在模块）
- **状态**：已修复并验证

---

## 一、问题现象

在前端左侧导航栏中，点击【数据集管理】（`/dataset/datasets` 及其详情页 `/dataset/datasets/:id`）后，**【数据管理】与【数据集管理】两个菜单项会同时高亮**。

反向操作则正常：点击【数据管理】（`/data/batches` 等）时，仅【数据管理】高亮，【数据集管理】不会跟着高亮。

通过浏览器 DOM 检查复现：访问 `/dataset/datasets/1` 时，侧边栏两个 `<a>` 均带有 `active` 类：

```
[
  {text:"首页",    classList:["nav-item"]},
  {text:"数据管理",  classList:["nav-item","active"]},   // ← 异常高亮
  {text:"数据处理",  classList:["nav-item"]},
  {text:"数据集管理",classList:["nav-item","active"]},   // ← 正确高亮
  {text:"算法广场",  classList:["nav-item"]}
]
```

## 二、排查过程

### 2.1 定位高亮逻辑

导航栏高亮由 [Sidebar.vue](file:///d:/Data/New_Codes/Composite_Projects/UAV-Visual-Intelligence-System-in-Agriculture/frontend/src/components/layout/Sidebar.vue) 的 `isActive` 函数控制：

```typescript
function isActive(section: string): boolean {
  const path = route.path
  if (section === 'index') return path === '/'
  return path.startsWith('/' + section)
}
```

导航项配置中：

| label | to | section |
|-------|----|---------|
| 数据管理 | `/data/batches` | `data` |
| 数据集管理 | `/dataset/datasets` | `dataset` |

### 2.2 根因确认

`isActive` 使用 `path.startsWith('/' + section)` 做**前缀匹配**。

- 数据集管理对应 `section = 'dataset'`，其匹配串为 `/dataset`；
- 而 `dataset` 字符串本身以 `data` 开头，故路径 `/dataset/...` 同样以 `/data` 开头；
- 于是当路由为 `/dataset/datasets/1` 时，`path.startsWith('/data')` 返回 `true`，【数据管理】也被判定为激活。

反向情况（`/data/...`）不以 `/dataset` 开头，因此不会连带高亮【数据集管理】——这解释了"只一边连动"的现象。

## 三、解决方案

将 `isActive` 的前缀匹配（`startsWith`）改为**按一级路径段精确匹配**，即取 `path.split('/')[1]` 与 section 做全等比较：

```typescript
function isActive(section: string): boolean {
  const path = route.path
  if (section === 'index') return path === '/'
  return path.split('/')[1] === section
}
```

- `/dataset/datasets/1` → 一级段为 `dataset`，仅【数据集管理】匹配；
- `/data/batches/1` → 一级段为 `data`，仅【数据管理】匹配；
- `index` 特判保持 `path === '/'` 不变。

此改动同时避免了其他潜在的相似前缀冲突（如未来新增 `data-*`、`process-*` 等一级路由时的误匹配）。

## 四、验证结果

在本地 `npm run dev`（Vite 5.4.21，端口 3001）环境下，通过浏览器 DOM 检查逐一验证：

| 访问路径 | 预期高亮 | 实测高亮 | 结果 |
|----------|----------|----------|------|
| `/dataset/datasets/1` | 仅【数据集管理】 | 仅【数据集管理】 | ✅ |
| `/data/batches/1` | 仅【数据管理】 | 仅【数据管理】 | ✅ |
| `/` | 仅【首页】 | 仅【首页】 | ✅ |

三处路径高亮均正确，无多余连动，修复有效。

## 五、经验教训

1. **路径段匹配优先于字符串前缀匹配**：用 `startsWith` 判断"当前路由是否属于某菜单分组"时，`data` 与 `dataset`、`process` 与 `processing` 等前缀包含关系极易造成误判。应始终基于路径的一级分段（`path.split('/')[1]`）做精确比较，或使用 vue-router 的 `route.meta`/`route.name` 分组标识。
2. **反向不对称是排查线索**：本 bug 表现为"A 连带高亮 B，但 B 不连带高亮 A"，正是 `startsWith` 单向包含关系（`dataset` 包含 `data` 前缀）的典型特征，可据此快速定位是哪对 section 存在前缀包含。
3. **前端展示类 bug 用 DOM 断言验证**：通过浏览器 evaluate 读取 `classList` 中的 `active` 类即可客观确认高亮，比肉眼截图更可靠、可回归。
